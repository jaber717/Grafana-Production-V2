# Grafana on RHEL 9 — production installation guide

Native Grafana OSS (RPM + systemd), the seven dashboards, two datasources (Zabbix, ClickHouse/Akvorado), two folders and the NOC playlist,
deployed and operated by one command: `grafana-platform`. Nothing here uses Debian, LXC or Docker. The LAB (grafana-01, Debian 12 LXC) is described in
[LAB-VS-PRODUCTION.md](LAB-VS-PRODUCTION.md) and is untouched by this release.

> **Status of the evidence** — release 2.0.0: unit tests and a **simulated** RHEL 9.8 host ([VALIDATION-V2.md](VALIDATION-V2.md)); not yet run on a real host
> ([LIVE-VERIFICATION.md](LIVE-VERIFICATION.md)). Release 1.0.1 recorded an acceptance on RHEL 9.6 ([VALIDATION-RHEL9.md](VALIDATION-RHEL9.md)).

## 1. Architecture

```
 users ──https:3000──▶ Grafana 13.2.3 (grafana-server.service, user grafana, SELinux Enforcing)
                         │  data: /var/lib/grafana (SQLite)        config: /etc/grafana/grafana.ini (rendered)
                         │  plugins: zabbix-app 6.8.0, clickhouse-datasource 4.22.0 (pinned, SHA-256 verified)
                         ├──https──▶ Zabbix API   (datasource uid zabbix-lab, read-only user, verified TLS)
                         └──https:8443──▶ ClickHouse of the Akvorado server (datasource uid netflow-clickhouse, user grafana_ro, verified TLS)
 grafana-platform (root)  ── /opt/grafana-platform/releases/<ver>, /etc/grafana-platform/{platform.env,secrets/,release.json}
```

* The package is the official signed RPM from `rpm.grafana.com`, pinned to **grafana-13.2.3-1**, held with `dnf versionlock`. The repository key is **vendored in this
  repository and its fingerprint (`B53AE77BADB630A683046005963FA27710458545`) is pinned**: the installer refuses any other key and verifies the package
  signature (`rpm -q --qf '%{RSAHEADER:pgpsig}'`).
* Dashboards, folders, datasources and the playlist are applied through the Grafana HTTP API by Node-based tools (idempotent, UIDs preserved).
* Secrets are files (`/etc/grafana-platform/secrets/`), read by Grafana through `$__file{…}`; nothing secret is in `grafana.ini`, in Git, or on a command line.

## 2. Server requirements

| Item | Requirement |
|---|---|
| OS | Red Hat Enterprise Linux **9.x** (any minor release; RHEL 8 and RHEL 10 are rejected by preflight), x86_64, SELinux **Enforcing**, firewalld **active**, NTP synchronised |
| CPU / RAM | 2 vCPU / 4 GiB (minimum 2 GiB) |
| Disk | `/` 15 GiB free; `/var/lib/grafana` on its own volume is recommended (WARN otherwise); 1 GiB per month of dashboards/annotations is generous |
| Repositories | RHEL BaseOS + AppStream (subscription, Satellite, or the installation ISO) — needed for `unzip`, `sqlite`, `xz`, `python3-dnf-plugin-versionlock`, `policycoreutils-python-utils`, and `nodejs` (AppStream, module `nodejs:20`) unless the offline bundle supplies Node.js |
| Inbound | `3000/tcp` (configurable) **only** from `GRAFANA_ALLOWED_CIDRS` (firewalld rich rules, one per CIDR) |
| Outbound (online install) | `rpm.grafana.com:443`, `grafana.com:443`; at run time: Zabbix API (`ZABBIX_URL`, 443/8443) and ClickHouse (`CLICKHOUSE_HOST:CLICKHOUSE_PORT`, 8443) |
| Outbound (offline install) | none for installation — see [OFFLINE.md](OFFLINE.md) |
| Time | the TLS certificate and Zabbix/ClickHouse sessions depend on it |

## 3. What you must prepare

1. The **offline package** built on a machine with Internet (`tools/build-offline-bundle.sh`) — [OFFLINE.md](OFFLINE.md).
2. The **values only you know**: Grafana address and allowed user subnets, the read-only Zabbix user, later the ClickHouse host/port/user.
3. For HTTPS (optional at first): a PEM certificate and key whose SAN contains `GRAFANA_DOMAIN`, plus the CA if private.

Secrets are **not** prepared as files by hand: `grafana-platform secret set zabbix-password | clickhouse-password | admin-password` prompts for them.
`secret-key` (encrypts datasource passwords inside the database — part of every backup decision, see [BACKUP-RESTORE.md](BACKUP-RESTORE.md)) and,
unless you set it, `admin-password` are generated by `install`.

## 4. Install

The exact procedure with single-line commands is **[INSTALL.md](../INSTALL.md)**. In outline:
`init-env` (configuration in one line) → `secret set zabbix-password` → `zabbix-check` → `preflight` → `install` → `item-map` + `apply` (NOC dashboards)
→ later ClickHouse: `config set CLICKHOUSE_ENABLED=yes …` + `secret set clickhouse-password` + `apply`.

`install` does, in order: preflight (stops without changing anything on a FAIL) → prerequisites and Node.js → imports the pinned Grafana key → installs and
version-locks `grafana-13.2.3-1` → secrets, TLS files, private CA trust → renders `grafana.ini` → installs the pinned plugins (SHA-256 verified) → firewalld
source rules → starts `grafana-server` → deploys the release (with its bundle) to `/opt/grafana-platform/releases/<version>` → applies folders, datasources,
dashboards and the playlist (deferred parts are skipped and reported) → installs a daily backup timer → full verification. Running it again changes
nothing that already matches; an interrupted install is resumed.

## 5. Configuration reference (`env/production.env.example`)

The template lists **every** setting; any other key is an error (with "did you mean …"). Yes/no settings accept yes/no, true/false, on/off, 1/0.
Show the effective values: `grafana-platform config show`. All keys with type and default: `grafana-platform config keys`.

| Variable | Meaning |
|---|---|
| `GRAFANA_DOMAIN`, `GRAFANA_HTTP_PORT` | name or IP users type in the browser (must be in the certificate for https); listener port |
| `GRAFANA_PROTOCOL`, `GRAFANA_ALLOW_INSECURE_HTTP` | `https` (default). `http` needs `GRAFANA_ALLOW_INSECURE_HTTP=yes` and is reported as WARN |
| `GRAFANA_TLS_CERT_FILE`, `GRAFANA_TLS_KEY_FILE`, `GRAFANA_TLS_CA_FILE` | https only: PEM files; installed to `/etc/grafana/tls` (key 0640 root:grafana); CA to the system trust store |
| `GRAFANA_ALLOWED_CIDRS` | **required**, no default: sources admitted to the port (firewalld rich rules) |
| `ZABBIX_URL`, `ZABBIX_USER`, `ZABBIX_CA_FILE`, `ZABBIX_TLS_SKIP_VERIFY` | Zabbix datasource (read-only user; password = secret `zabbix-password`) |
| `ALLOW_INSECURE_DATASOURCES` | `no` (default). `yes` permits `http://` Zabbix, ClickHouse without TLS, and `ZABBIX_TLS_SKIP_VERIFY=true` — each reported as WARN |
| `CLICKHOUSE_ENABLED` | `yes` (default) / `no` = defer NetFlow: no ClickHouse datasource, NetFlow dashboards, playlist or `clickhouse-password` |
| `CLICKHOUSE_HOST`, `CLICKHOUSE_PORT`, `CLICKHOUSE_SECURE`, `CLICKHOUSE_USER`, `CLICKHOUSE_CA_FILE` | ClickHouse datasource (empty port = 8443 with TLS, 8123 without) |
| `ZABBIX_ITEM_MAP_FILE`, `ALLOW_NOC_WITHOUT_ITEM_MAP` | NOC dashboards ([ZABBIX-ITEM-MAP.md](ZABBIX-ITEM-MAP.md)); `yes` defers them while the map is missing or incomplete |
| `PACKAGE_SOURCE`, `BUNDLE_DIR` | `auto` (default: bundle next to the release if present, else Internet), `repo`, `bundle` ([OFFLINE.md](OFFLINE.md)) |
| `SECRETS_DIR`, `BACKUP_DIR`, `BACKUP_KEEP`, `BACKUP_GPG_PASSPHRASE_FILE` | locations / retention / optional archive encryption |

Changing a value: `grafana-platform config set KEY=VALUE` (validated; the old file is kept as `.previous`), then `grafana-platform install`.

## 6. Day-2 operations

| Task | Command |
|---|---|
| Health, security and content check (PASS/WARN/FAIL, non-zero exit on FAIL) | `grafana-platform verify` |
| One-screen summary | `grafana-platform status` |
| Backup now (daily timer `grafana-platform-backup.timer` does it too) | `grafana-platform backup [--include-secrets]` |
| Restore | `grafana-platform restore <archive> [--yes]` |
| Bare-host recovery | `grafana-platform restore <archive> --bootstrap`, then `install`, then `restore <archive> --yes` |
| Upgrade to the versions pinned in a newer release | unpack the new release, `sudo bin/grafana-platform upgrade` |
| Roll back the last upgrade | `grafana-platform rollback` |
| Logs | `/var/log/grafana-platform/*.log`, `journalctl -u grafana-server` |

Upgrade (`grafana-platform upgrade`): preflight → **backup** (database, config, content export; the previous RPM is cached) → package, plugins, configuration and content move to the
release's pins → full verification. If any step or the verification fails the tool **rolls back automatically** (previous RPM + the pre-upgrade backup) and exits non-zero.
`rollback` does the same on demand; data created after the upgrade is not in the pre-upgrade backup and is lost by a rollback (it is the price of returning to the old schema).

## 7. Troubleshooting

| Symptom | Check |
|---|---|
| `preflight` FAIL on the certificate | `openssl x509 -in cert -noout -text` — SAN must contain `GRAFANA_DOMAIN`; the key must match; the chain must validate against the system store or `GRAFANA_TLS_CA_FILE` |
| Datasource `health` FAIL, "certificate signed by unknown authority" | the CA file named in `ZABBIX_CA_FILE` / `CLICKHOUSE_CA_FILE` is installed by `install`; re-run it. Grafana reads the system trust store at start (the installer restarts it) |
| Datasource `health` FAIL, "context deadline exceeded" | network path/firewall to Zabbix or ClickHouse (ClickHouse admits only the Grafana source address) |
| NOC dashboards missing | deferred (`ALLOW_NOC_WITHOUT_ITEM_MAP=yes`) or no complete map: `grafana-platform item-map`, then `apply` |
| A setting seems ignored | `grafana-platform config show` prints what the tool actually uses; unknown or misspelled keys are reported as errors |
| SELinux denial | `ausearch -m avc -ts recent`; Grafana itself runs unconfined (see [SECURITY-PRODUCTION.md](SECURITY-PRODUCTION.md)) |
| Dashboard restored away still visible | the install clears `/var/lib/grafana/unified-search` on restore; if you restore by hand, remove it before starting Grafana |
| `grafana-platform: command not found` | `/usr/local/sbin/grafana-platform` exists after the first install; before that use `bin/grafana-platform` of the unpacked release |
