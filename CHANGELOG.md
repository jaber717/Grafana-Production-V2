(DOWN first, link to NOC — Device Health), the devices' active Zabbix problems, CPU and memory trends. Operator guide:
[docs/NOC-COMMAND-CENTER.md](docs/NOC-COMMAND-CENTER.md). Additive: the existing dashboards, data sources, credentials and services are
not changed; `install.sh --dashboards` creates it (re-running finds it unchanged).

  bookmark, Device Type filter, missing metrics, DOWN and UNKNOWN devices, refresh, drill-down).
* `tests/noc/zabbix7-api.mjs`: `trigger.get`, `problem.get`, `user.get`; `--fleet` (24 network devices, an unknown-state switch, a
  firewall without CPU/memory items, an agent-monitored firewall).
* `tests/check-generator.sh` (release gate step 8) also proves the NOC generators reproduce the committed NOC dashboards.

### Fixed

  flagged the 2.3.0 line as a false positive.

### Tested (test VM + test Zabbix — not production)

  Browser acceptance 118/118, simulation 98/98, download tests 19/19, unit tests 28/28, release gate PASS
  ([docs/evidence/command-center/](docs/evidence/command-center/)).

### Unchanged

## [2.3.0] - 2026-10-26

**Dynamic NOC dashboards.** "NOC — Device Health" and "NOC — Network Overview" (same uids) no longer contain any device, host, item or
interface: Device Type → Device → Interface are chosen in Grafana and read from Zabbix (host groups, interface-discovery tags, item tags
and names). Details: [docs/NOC-DASHBOARDS.md](docs/NOC-DASHBOARDS.md). NetFlow dashboards, data sources and credentials are unchanged.

### Changed
* `dashboards/noc/*.json` regenerated by `tools/build-noc-dashboards.py`: variables `devtype` (custom, host-group regex per type),
  `device` (Zabbix host query, refreshed on load), `interface` (Zabbix item-tag query, multi); panels for ICMP/SNMP availability, uptime,
  CPU, memory, interface status, traffic, errors — selected by item tag + name, never by key.
* Setup: the LAB item-map step (router host names) is replaced by the **Device Type** step: the host groups that exist in Zabbix are
  listed and mapped to Router / Switch / Firewall (`NOC_GROUPS_*`; defaults: names containing router|rtr, switch, firewall).
* Preflight no longer checks a LAB item map (no dashboard uses item ids). The `item-map` command remains as a legacy tool.
* Managed Zabbix data source: cache TTL 5 min (`ZABBIX_CACHE_TTL`, was the plugin default 1 h), so new hosts appear in the pickers sooner.

### Added
* `tests/noc/zabbix7-api.mjs` (strict Zabbix 7.0 API stand-in, five vendors), `tests/noc/ui-acceptance.py` (browser test of the pickers).

## [2.2.3] - 2026-10-26

Production (2.2.2): all 7 dashboards imported, but both NOC dashboards said "Zabbix not connected" although a Zabbix data source works in
Grafana, and `sudo grafana-platform setup --zabbix` answered "command not found".

### Fixed
* `sudo grafana-platform` on RHEL: RHEL's sudo `secure_path` (/sbin:/bin:/usr/sbin:/usr/bin) has no /usr/local/sbin. The command is now
  also linked as /usr/sbin/grafana-platform (removed by `uninstall`).
* A Zabbix data source created in Grafana by hand is now used instead of being ignored: `--dashboards` (and `--zabbix`) find it and ask
  "Use the Zabbix data source that already exists ...?". Chosen: `ZABBIX_DATASOURCE_UID=<its uid>`, the NOC dashboards point at it, the
  installer never creates a second one and never modifies it (apply and verify only read it and its /health).
* `--dashboards` connects Zabbix first when it is not connected (`ZABBIX_ENABLED=no`), then builds the item map and imports.

## [2.2.2] - 2026-10-26

**All 7 dashboards are always imported; nothing is silently skipped.** Production (2.2.1): both folders NetFlow and NOC existed but were
empty while the install reported 0 FAIL. Cause: every dashboard was *deferred by design* — the 5 NetFlow dashboards because ClickHouse was
not connected (`CLICKHOUSE_ENABLED=no`; they query only ClickHouse), the 2 NOC dashboards because the Zabbix item map was missing/incomplete
(router host names not given) — and each deferral was only a WARN, which the setup screen filtered out; the folders were created anyway.

### Changed
* Every managed dashboard is deployed. One whose setup is incomplete carries a notice panel at the top that says what is missing and the
  one command that completes it; it is updated automatically (notice removed) once that is done:
  * NetFlow without ClickHouse: datasource reference kept (`netflow-clickhouse`), panels empty until `setup --clickhouse`.
  * NOC with a missing/partial item map: mapped Zabbix item ids are used; unmapped ones are left **empty** (a LAB id is never sent to
    another Zabbix); the notice lists the affected panels. `ALLOW_NOC_WITHOUT_ITEM_MAP=no` still refuses instead.
* Install summary and `verify` report what Grafana actually holds, read back through its API (`scripts/dashboards-report.mjs`).

### Added
* `sudo ./install.sh --dashboards` (= `grafana-platform setup --dashboards`): (re)imports all dashboards into the running Grafana —
  no package, grafana.ini, service, firewall or datasource change, no restart; updates the release files, asks the Zabbix host names the
  item map cannot find, applies idempotently (matched by uid: no duplicates), and prints the API read-back.

## [2.2.1] - 2026-10-25

**Interrupted downloads are recovered, never repeated, never trusted unchecked.** Production: the single 336 MB release-asset download
(2.1.1) closed after exactly 199,229,440 bytes (190.0 MiB, `curl: (18)`). No change to dashboards, UIDs, pins or configuration.

### Fixed
* An interrupted download is reused: any file named like an offline archive near the release, in /root, /tmp, /var/tmp, the cache or the
  invoking user's home — complete, cut off, `*.part`, damaged — is read (never changed) and every 192 KiB piece in it whose SHA-256 matches
  the pinned manifest is kept; only the rest is fetched (`lib/seedparts.py`). A 190 MiB prefix supplies 1023 of 1717 pieces.
* A cut-off archive named `*.tar.gz` no longer stops the installer ("cannot be used"): incomplete gzip streams are not offered as archives,
  and an archive that fails its pins falls through to the next source.
* Single-archive download (fallback): the partial file is kept on any network error (2.1.1 deleted it) and continued with a Range request;
  data is appended only from a `206` whose `Content-Range` starts exactly at the current size. `200` (range ignored) or a wrong start:
  nothing appended, partial kept, clear message. Up to 6 continuing attempts; final SHA-256 against the pin, a mismatch is kept as `*.rejected`.
* The 1-byte reachability probe stops after 1 MB (`--max-filesize`) when a server ignores Range, instead of streaming the whole file.
* `tests/download/run-download-tests.sh`: 19 checks against a fault-injecting server (cuts, ignored/wrong ranges, tampering, damaged partials).

## [2.2.0] - 2026-10-25

**Packages from GitHub in small pieces.** The production proxy cuts the single 336 MB release-asset download after ~895 KB; the packages now
come from `codeload.github.com` (the host the source download already uses) in 1717 responses of < 200 KB each. Root cause, design and
tests: [docs/DISTRIBUTION.md](docs/DISTRIBUTION.md). No change to dashboards, UIDs, pins, configuration or the questions asked.

### Added
* `packages` branch: the pinned Grafana RPM, both plugins and Node.js split into 192 KiB pieces (one commit per piece);
  `packages/MANIFEST.txt` on main lists every piece with its SHA-256; `tools/publish-packages.sh` re-creates both.
* Package source "pieces": fetched 4 in parallel, each SHA-256 checked, retried 5 times, kept across runs (a re-run continues), joined and
  checked against the pins. Preferred over the single release-asset download, which stays as a fallback.

### Fixed
* `curl-minimal` (RHEL 9 default) satisfies the curl prerequisite; before, the check failed or `dnf install curl` conflicted.
* Preflight no longer requires Node.js before the packages are fetched when they include it.

## [2.1.1] - 2026-10-25

**Fix: the pinned-archive download did not work behind an explicit HTTP proxy** (found on the production VM: "the Grafana package cannot be obtained"). No change to dashboards, UIDs, pins or the install flow.

### Fixed
* The download of the pinned offline archive from GitHub now uses an explicit proxy: `GP_PROXY`, else `https_proxy`/`HTTPS_PROXY`, else `proxy=` in `/etc/dnf/dnf.conf`. Before, the installer had no proxy support and `sudo` removed the operator's proxy variables. `install.sh` now hands the proxy through `sudo`.
* Reachability is checked with a 1-byte GET over the same path as the download (GitHub redirect followed, HTTP errors count as failures) instead of a HEAD request that also counted a proxy's error page as success.
* Transient errors (incl. 502/503/504) are retried 3 times; connect timeout 20 s.
* A proxy that re-signs TLS (certificate not trusted on the host) no longer blocks: the download continues with a WARN, because the file is accepted only if its SHA-256 equals the pin in this release, and every RPM/plugin/Node artifact inside is checked against its own pin.
* The failure message now shows curl's actual error, the proxy used, and a fix for that error (proxy refused / timeout / DNS / not allowed).
* Internal connections (local Grafana, Zabbix and ClickHouse probes) never use a proxy, even when proxy variables are exported.

## [2.1.0] - 2026-10-22

**One-command installation.** No change to dashboards, UIDs, datasource templates or any pin.

### Added
* `install.sh` / `grafana-platform setup`: the single entry point. Asks only address, allowed networks, http/https, Zabbix (optional), ClickHouse (optional) and the admin password; writes `/etc/grafana-platform/platform.env` and the secrets itself; tests the Zabbix login and ClickHouse `/ping` **before** installing (retry or skip); installs; builds the Zabbix item map and asks for differing router host names; prints a short summary. Re-run = Enter keeps everything; `--zabbix`, `--clickhouse`, `--reconfigure`, `--yes`.
* Automatic package source: `bundle/`, or any `grafana-platform-*-rhel9-offline.tar.gz` near the release or in `/root` (including the published 1.0.1 archive), or rpm.grafana.com, or a one-time download of the pinned archive (`BUNDLE_FALLBACK_URL`, SHA-256 pinned; custom `BUNDLE_URL` requires `BUNDLE_URL_SHA256`). Every artifact verified against this release's pins.
* `ZABBIX_ENABLED` (Zabbix becomes optional like ClickHouse); `lib/probe.py` (read-only connection tests, no Node needed).

### Changed (fewer blockers, same protections)
* NOC dashboards are deferred by default when the item map is missing or incomplete (`ALLOW_NOC_WITHOUT_ITEM_MAP` default `yes`; `no` restores the strict check). Never deployed half-mapped.
* SELinux not Enforcing: WARN instead of FAIL (Grafana runs unconfined on RHEL either way). Optional tools (sqlite for backups, versionlock plugin, SELinux helpers) only warn; the dnf repository count is no longer checked on its own.
* Still blocking: wrong OS/arch/root, firewalld inactive, package not obtainable or not matching its pins, missing required tools, disk, port, foreign Grafana, invalid certificate, insecure transport without explicit consent.

## [2.0.0] - 2026-10-22

First release of **Grafana-Production-V2**, an independent continuation of `jaber717/Grafana` 1.0.1 (commit `7c5b9f9`; that repository is not modified).
**No change to any dashboard, dashboard/folder/datasource UID, datasource template, plugin or Grafana version pin.** Root causes: [docs/ROOT-CAUSE-V2.md](docs/ROOT-CAUSE-V2.md).

### Fixed
* `ALLOW_INSECURE_DATASOURCES=yes` not honored: one strict parser (`lib/envparse.py`) for bash and Node. 1.x silently dropped indented lines containing `#`, compared case-sensitively, ignored unknown/misspelled keys and accepted duplicates; 2.0 accepts yes/no/true/false/on/off/1/0 in any case and turns every ambiguity into an error naming the line and the fix. The key is now in the template.
* Offline installation: `PACKAGE_SOURCE=auto` (default) uses `<release>/bundle` automatically; `BUNDLE_DIR` defaults to it; the bundle is deployed with the release and the RPM cached for rollbacks; package sources are checked only when something must be installed; one FAIL instead of two.
* Item map: the 7 previously unresolved descriptors (SNMP uptime behind the "UP" signal) resolve through standard template keys (REVIEW output); production host names via `--host`; partial maps can be deferred.
* `install` aborted when `clickhouse-password` was absent; Node.js on RHEL 9 (old default stream installed before the module stream was selected); "read-only" preflight created `/var/lib/grafana`; playlist referenced undeployed dashboards.

### Added
* Commands: `init-env` (configuration in one line), `config set|show|check|keys` (validated edits, previous file kept), `secret set|status` (prompted, never echoed), `zabbix-check`, `item-map`, `apply`, `uninstall [--purge]`.
* Deferral without broken objects: `CLICKHOUSE_ENABLED=no` (no ClickHouse datasource, NetFlow dashboards or playlist, no ClickHouse secret); `ALLOW_NOC_WITHOUT_ITEM_MAP=yes` also for incomplete maps.
* Every preflight FAIL is followed by a `-> fix:` line with the exact command; read-only reachability probes for Zabbix (`apiinfo.version`) and ClickHouse (`/ping`).
* `tools/zabbix-item-map.mjs`: user/password login with the datasource credentials (session per Zabbix version, logout), `--host`, `--set`, `--merge`, `--search`, `--check`, request timeouts.
* Offline builder: finds the RPM through the repository metadata when it is not at `/Packages/`; overridable download bases (tests).
* Tests: `tests/unit/v2-*.test.mjs` (parser parity bash/Node, deferral, item-map tool), `tests/sim/run-sim.sh` (simulated RHEL 9.8 host, executes INSTALL.md verbatim, reproduces the 1.0.1 failure); release gate runs shellcheck and the simulation.
* Documents: `INSTALL.md`, `docs/ROOT-CAUSE-V2.md`, `docs/MIGRATION-FROM-V1.md`, `docs/ROLLBACK.md`, `docs/LIVE-VERIFICATION.md`, `docs/VALIDATION-V2.md`.

### Known limitations
Not yet run on a real RHEL host, real Grafana, the production Zabbix or ClickHouse; the offline bundle was not built against the real download sites (they were unreachable from the build environment). See [docs/LIVE-VERIFICATION.md](docs/LIVE-VERIFICATION.md).

## [1.0.1] - 2026-10-11

### Known limitations
